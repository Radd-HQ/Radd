# Page-space settings and template directory — RADD-1115

Page-space settings now searches and pages in 50-row windows. Navigation recognizes management permission in any readable space, and each row checks that space for rename/public/delete controls. Space creation, template CRUD and link reindex retain the API's global page.manage requirement. Grant/revoke controls use role.update rather than page.manage. The legacy space-grant read now checks page.read in the requested space instead of requiring access to an unrelated issue project; unreadable spaces are refused.

Editing a space uses a separate form component and shared modal, so directory refreshes cannot unmount an unfinished draft. Empty-space deletion asks for confirmation; a non-empty response requires an additional explicit cascading-delete confirmation. Cancel preserves the space and pages. Last-page removal recovers the previous window, and read/write failures stay visible with retry where appropriate.

Templates use a separate lean directory. SQL applies readable-space visibility, literal name/description search, count and stable name/ID ordering before returning a window. Rows include the permitted space name but omit markdown; opening an editor fetches one body through a visibility-filtered direct endpoint. The scope selector uses lazy shared choices and exact saved-value resolution, including the global “Every space” value. Existing complete template readers and placeholder rendering remain compatible. Known filtered counts are displayed as matches rather than a misleading count against an unknown total.
