## Additional defects uncovered and cleanup

- Plugin uninstall could crash on legacy JSON `null` token scopes. The sweep now treats both SQL NULL and JSON null as unrestricted legacy scopes; new token rows use SQL NULL. A database test explicitly inserts the legacy representation before uninstalling a plugin.
- Malformed scope containers such as `projects: []` or `global: false` caused internal errors; validation now returns 422.
- WebSocket identity resolution now honors view-as and rechecks sessions on an absolute deadline. Sending subscription traffic cannot keep a revoked session alive indefinitely.
- A late workflow refusal could leave merge rows moved when an outer caller caught the exception. The merge operation now owns its rollback savepoint.
- The mobile issue header clipped actions despite the document having no horizontal overflow. The header now wraps, and the real-browser script checks action bounds as well as page width.
- Removed unused runtime imports/bindings while retaining permission/existence calls and registration imports. Restored explicit public service/SDK exports; aligned frontend user-source vocabulary; removed obsolete item-list factories, keys and mutation cache writes. Updated obsolete auth/comments rollout explanations.
- Contributor paths, module seams, deployment limits and CI bootstrap instructions are documented. Historical migrations, public redirects, secret adoption and transaction-buffer middleware were retained because they serve compatibility or transaction invariants.

From `web/`: `npm run check`. From the repository root: `server/.venv/bin/ruff check server/src`.

From `server/`, with the existing isolated local test database:

```bash
RADD_DATABASE_URL=postgresql+psycopg://radd:radd@127.0.0.1:5456/radd \
RADD_TEST_DATABASE_URL=postgresql+psycopg://radd:radd@127.0.0.1:5456/radd_audit_test \
.venv/bin/python -m pytest -q
```

The pytest fixture drops and recreates its selected database. Never point it at either populated `radd` database. Run suites sequentially against a shared disposable database.

For populated-data checks, start the app with `RADD_RUN_WORKERS=false` against a development database, then run `live-check.py` with the matching development database URL and `node research/audit-2026-09-09/live-browser.mjs` from the repository root. The latter needs the temporary cookie file written by the former and removes it after revocation. Inspect the selected dataset before running these local audit tools elsewhere.
