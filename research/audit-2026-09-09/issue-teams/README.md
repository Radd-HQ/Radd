## Behavior

Issue creation, properties and bulk assignment now share a lazy 50-row team search instead of complete team catalogs. Existing selected team IDs resolve directly; issue properties may reuse their already-authorized item label. Clearing retains the existing empty/null wire values and native field locks remain in force.

GET `/teams/references` accepts at most 50 UUIDs and returns only authorized team names and optional member counts. Missing IDs are omitted, restricted credentials lacking global `team.read` receive no names/counts, and GET remains usable during read-only view-as. Count requests aggregate one groups-owned recursive membership projection per team window. Direct membership, shared roots, nested diamonds and cycles deduplicate each `(team,user)`; inactive users remain counted to match existing roster semantics. Names-only requests never load rosters.

The internal-note composer keeps the entire audience draft while showing at most 50 selected names/counts. The nested team picker stages additions across search pages and applies them together; Escape discards staged additions without changing the underlying audience. Errors retain IDs and expose retry. Counts describe team membership, not actual notification recipients: readers still need issue/internal-note access and the existing author/project-manager exceptions remain. Comment headers hydrate only their three-name previews in bounded batches; larger saved audiences have a complete paged dialog. The complete audience UUID wire contract remains compatible.

Comment audience validation now checks only the submitted IDs through the public `teams.existing_ids` facade. Invalid IDs are rejected before replacing old restrictions; public comments clear team restrictions. This is audience replacement protection, not a new claim that every comment-service update is atomic if a caller catches an exception.

The browser discovered another complete team reader in the Participants remote. Its person/team picker now mounts only while adding, with debounced server search, 50 visible rows and one lookahead row. Search/kind/page identities are distinct, stale requests cancel, errors can retry and empty later pages recover. It retains the existing public user directory's project-access annotation: a person without access is still addable and the UI explains that addition grants access. Inactive and existing participants are disabled; saved participant chips remain complete. Team options are lean ID/name choices. The project authority-map computation and full saved participant list are separate outstanding readers.
