# Custom-field directory, capabilities and scope choices — 2026-09-10

RADD-1115 checkpoint: verified locally, not released. The full [outstanding-work ledger](../OUTSTANDING.md) remains active.

## What changed

Field settings now requests 50-row summaries instead of the complete field registry and project catalog. Summaries omit option/default bodies and include a project count and a current-window restriction flag. SQL filters authority and literal name/key search before counting and paging, with stable creation/ID ordering. Only the selected definition loads its full body.

The server supplies separate create, update, delete and access-management capabilities. Scoped-only field administrators can reach settings and definitions without unrelated issue readership. Every multi-project capability requires authority over the complete scope; global fields require global authority. Existing issue-member metadata reads retain their complete registry contract. Empty-scoped admin keys receive no data or capabilities, and expired grants withdraw admission. The earlier independent current/destination scope authorization fix remains in force.

Project choices are filtered by the requested field.create or field.update permission, rather than by issue readership. Selected project labels use at most 50 authorized ID references per request, with full scope drafts retained off-page. Names require either project visibility or field authority. Scope IDs have set semantics in the legacy API; the editor sorts existing IDs to stabilize its selected-project windows. Scoped-only creation requires at least one project, and removing the final project or making a field global requires global authority.

The settings rail, FieldEditor, FieldOptionsSection and FieldProjectScope now have separate responsibilities. Selected editors remain mounted across directory search, paging and refresh; new definitions can open outside the current search. Failed reads provide retry controls. A failed option-usage count blocks removal until the count succeeds. Delete-only actors get the correct navigation and control, with last-page recovery. Deleting a definition now cancels/excludes its direct read from refresh before clearing its cache, avoiding a redundant 404 while the rail reloads.
