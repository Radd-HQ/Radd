# Spec 46 — AI layer (optional, provider-agnostic)

The AI pillar, kept strictly optional: a new **`ai` module** — **NO tables**
— dormant unless a provider is configured. Provider-agnostic per the locked
decision: OpenAI-compatible (`base_url` — covers LiteLLM/Ollama/vLLM/OpenAI)
**and** native Anthropic, selected by `RADD_AI_PROVIDER`.

## Config

`RADD_AI_PROVIDER` ("" = disabled | "openai" | "anthropic"),
`RADD_AI_BASE_URL` (default `https://api.openai.com/v1` /
`https://api.anthropic.com`), `RADD_AI_API_KEY`, `RADD_AI_MODEL`,
`RADD_AI_MAX_TOKENS` (1024), `RADD_AI_TIMEOUT_SECONDS` (30).

## Provider seam

`ai/provider.py`: `async complete(system, user_prompt) -> str` — httpx to
`{base_url}/chat/completions` (OpenAI shape) or `{base_url}/v1/messages`
(Anthropic shape, `x-api-key` + `anthropic-version` headers). One function,
two payload builders (pure, unit-tested). Errors → 502 with a clean message.

## Endpoints (all require the caller's ordinary permissions; 403 when module
configured but caller lacks item access; 404-style clean error when disabled)

- `POST /items/{id}/ai/summarize` (item.read) → `{summary}` — description +
  recent comments + state/history digest, prompt asks for a tight
  hand-off-style summary. **Not stored** — returned to the caller.
- `GET /items/{id}/similar?limit=5` (item.read) → candidate duplicates:
  **FTS-first** (the existing search module's index over key/title/
  description via a public seam — add `search.service.similar_to_text` if
  missing) and, when AI is enabled, an LLM rerank/filter pass that scores
  candidates 0–1 for "same underlying issue" and returns
  `{item_key, title, score, reason}`. With AI disabled the endpoint still
  works (FTS rank only) — dup detection degrades, never disappears.
- `POST /slq/nl {question, workspace_id}` (item.read) → `{slq, explanation}`
  — natural language → SLQ using a system prompt embedding the frozen SLQ
  grammar + the workspace's field registry (names/types/options live);
  the produced query is VALIDATED by compiling it server-side before return
  (invalid → one retry with the error in-prompt, then 422).
- `GET /ai/status` → `{enabled, provider, model}` (any member) — the
  frontend gates UI affordances on it.

## Frontend

Issue page: an "AI" section in the rail when `/ai/status` is enabled —
Summarize button (renders returned markdown in a dismissible panel) and a
"Find similar" affordance listing scored candidates as links. List/SLQ bar:
an "Ask" input (visible when enabled) that calls `/slq/nl` and drops the
returned SLQ into the existing editor (user sees + can edit the query —
transparency over magic).

## Tests

Pure: both payload builders, prompt assembly (registry → field list),
NL→SLQ validation-retry decision. No live-provider tests.

## Known simplifications

- pgvector semantic search deferred: the stock postgres:16 container lacks
  the extension; the outbox-indexer pattern + this provider seam make it a
  drop-in when the image gains pgvector (documented in PLAN §8).
- No auto-triage automation action yet (the rules engine's action union is
  the seam); no streaming responses; summaries not cached.
- Agents-as-principals ships via MCP (spec 45) — this module is the
  human-facing AI surface.
