# Permission and notification scope selectors — RADD-1115

EffectivePermissions now opens project/wiki catalogs lazily in 50-row windows. Choosing a different scope kind clears the old target and waits for an explicit selection before resolving; it no longer displays instance-wide permissions while a project/space is being chosen. Selected references resolve directly, instance-wide clears both scope parameters, and resolution failures expose retry. The inspector remains gated by the existing global user.manage API.

Notification subscription choices use one bounded endpoint per requested scope, with the existing project/wiki/team authorization gates. SQL excludes the caller's existing subscriptions before search, count and pagination, so a window full of subscribed targets cannot conceal later choices. Rows contain only UUID value, name and key/slug hint. The grant/automation choice contracts remain compatible. Failed Add retains the selected target for retry; successful save refreshes candidates. Removing a subscription restores its candidacy while preserving the remaining policy and digest setting.

Reading a saved wiki subscription also exposed a stale call to the removed `pages.service.list_spaces` method. The corrected public `space_names` seam projects only IDs/names from the already-authorized saved set. It does not load every space or aggregate page counts. Four new PostgreSQL/HTTP cases cover this path, stable windows, authorization, write/read parity, exclusions, validation bounds and absent-wiki handling.
